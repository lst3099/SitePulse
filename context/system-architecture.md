# 系统架构与核心业务规则

**状态**：已确认基础事实；未决项见 [drafts/requirements-confirmation.md](../drafts/requirements-confirmation.md)  
**更新时间**：2026-08-26

## 总体链路

```text
项目与人员主数据
  → 系统登记海康物理设备
  → 项目绑定已登记设备并在绑定时配置出入口
  → 人员、人脸、门禁权限同步
  → 设备识别人脸并产生原始事件
  → 平台接收/补传/去重事件
  → 按项目 + 人员 + 日期计算考勤结果
  → PC 管理与移动端查询
```

## 组件职责

| 组件 | 主要职责 |
| --- | --- |
| 平台 | 管理人员、项目、健康/年龄规则、项目关系、设备登记、出入口、设备绑定、考勤结果和工器具。 |
| 海康设备 | 识别人脸、校验门禁、开门并产生原始事件。 |
| 设备接入服务 | 登录设备、查询能力、同步人员/人脸/权限、接收实时事件、补传历史事件、记录设备状态。 |
| PC 端 | 提供管理员和项目负责人的管理、查询、补录、告警和导出能力。 |
| 移动端 | 查询本人考勤、项目范围内信息、个人信息和人脸同步状态，不承担扫码打卡或补录。 |

## 核心数据关系

- 一个项目可以绑定多台设备，并在设备绑定关系中配置多个出入口。
- 设备登记是全局物理设备主数据；出入口名称和方向是项目设备绑定关系中的配置属性。
- 项目侧只能从已登记且未绑定其他项目的设备中选择设备；同一物理设备同一时间只允许存在一个有效项目绑定。
- 设备绑定至少包含项目、设备、出入口、进出方向、绑定状态和生效时间。
- 一个施工人员可以同时或先后关联多个项目。
- 人员主档案、项目人员关系、设备权限和移动端账号分别控制。
- 人员离场后解除项目关系并撤销项目设备权限，但保留人员档案、历史关系和历史考勤。

## 考勤规则基线

- 设备原始事件不修改、不合并、不删除；重复事件按设备 ID、事件流水号、事件时间和人员等信息去重，并保留事件来源。
- 考勤计算以“项目 + 人员 + 日期”为主键，汇总项目全部出入口的有效记录。
- 人脸识别成功即计入有效考勤；没有开门反馈时仍计入，同时保留设备异常信息。
- 进门或出门任一方向缺失时，当前方案仍允许形成出勤结果并保留异常标识。
- 全天没有有效事件和有效补录时，按工作日规则计算缺勤。
- 平台可以新增补录并重新计算考勤；设备原始事件不被修改。

## 权限与异常

- 首次授权同步失败时，设备没有有效权限，人员不允许进入。
- 平台要求撤销权限但设备同步失败时，设备可能暂时保留原权限；平台必须记录同步异常和时间。
- 年龄超过项目阈值后次日默认禁止进入；初始阈值为 60 岁，提前 30 天预警，特殊授权需要有效期。
- 设备离线、权限过期和同步失败需要产生管理侧告警；未登记人员只保留刷脸记录，不单独产生告警。
- 设备数据向住建委平台的直传方式、网络/网关和通信协议仍待确认。
