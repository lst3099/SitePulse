# SitePulse 术语

平台文档和 AI 输出应优先使用下列术语，避免同一概念多种叫法。

| 术语 | 定义 | 使用说明 |
| --- | --- | --- |
| 项目 | 施工现场的业务管理单元，当前与“工地”统一称为项目。 | 不在新文档中混用“工地”作为正式实体名。 |
| 人员主档案 | 人员的全局基础信息。 | 不因离场、转项目或移动端账号停用而删除。 |
| 项目人员关系 | 人员与具体项目之间的关联。 | 与人员主档案分开保存，可保留历史关系。 |
| 打卡人员 | 仅能登录移动端查看本人相关信息的人员角色。 | 不等同于设备门禁权限。 |
| 设备 | 现场海康人脸识别、门禁或闸机设备。 | 设备产生识别、权限和通行相关事件。 |
| 设备绑定关系 | 设备与项目、出入口、进出方向及生效状态之间的关系。 | 设备产生的记录通过绑定关系归属项目。 |
| 进门设备 / 出门设备 | 由设备绑定关系配置的方向字段。 | 平台不根据事件自行推测方向。 |
| 原始设备事件 | 设备产生并上传的原始识别/通行记录。 | 不修改、不合并；需要去重时保留来源标识。 |
| 有效设备事件 | 当前规则下可参与考勤计算的刷脸记录。 | 已确认“存在刷脸记录即可作为有效事件”，细节仍以最终算法为准。 |
| 平台考勤结果 | 平台按项目、人员、日期汇总事件和补录后计算出的结果。 | 与原始设备事件分层保存，允许按规则重新计算。 |
| 补录 | 管理员为缺失的进门或出门记录新增一条平台记录。 | 错误补录应作废并填写原因，不能修改设备原始事件。 |
| 人脸同步 | 将平台人员、人脸和门禁权限同步到项目设备。 | 需要展示同步时间、状态和失败原因。 |
| 平台权限 / 设备已生效权限 | 平台计算出的应有权限 / 最近一次成功同步到设备的权限。 | 两者可能因同步失败暂时不一致。 |
| 工器具 | 现场需要维护状态和定期检查的工具或资产。 | 与人脸考勤主链路分开管理；二维码是工器具标识。 |
