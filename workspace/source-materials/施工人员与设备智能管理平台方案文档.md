# 二、方案概览与架构

## **2.1解决方案概览**

- 现有系统通过手机扫描二维码完成项目上下班打卡，存在代打卡、无法确认实际在场等问题。本次方案将现场打卡方式调整为海康人脸识别设备/闸机打卡，通过人脸验证与实际通道通行结合，提高考勤记录的真实性。
- 平台负责施工人员、项目、健康报告、年龄限制、项目权限和考勤结果管理；海康设备负责人员识别、门禁校验、开门和原始通行事件产生；设备接入服务负责平台与海康 SDK 之间的数据交互。
- 项目可以配置多个出入口，不同出入口的设备统一纳入同一个项目的考勤统计。只要设备绑定到当前项目，设备产生的打卡记录就归属当前项目。
- 本方案同时建设人员信息管理、人脸门禁考勤、考勤异常处理、设备管理、工器具二维码和定期检查等功能，并保留 PC 端管理和 APP 查询能力。
- 本版方案暂不展开完整网络/网关部署、住建委数据对接、现场安装、现有系统技术栈、数据安全和性能指标等内容；海康门禁 SDK 对接的最小落地范围见 5.5 节。

### 2.1.1人员与项目管理

- 建立统一的施工人员信息库，维护姓名、身份证号、籍贯、民族、性别、出生日期、年龄、手机号、施工队伍、施工队伍负责人/老板组、专业/工种、是否工长、人员状态等信息。
- 人员主档案与项目人员关系分开管理。同一个人可以同时属于多个项目，人员转项目时保留原项目历史关系，人员离场后解除项目关系但保留人员档案和历史考勤。
- 支持 Excel 批量导入人员和项目人员关系，支持按照项目、施工队伍、专业、状态等条件导出数据。

### 2.1.2海康人脸门禁考勤

- 平台登记海康设备；项目绑定设备时选择出入口和进出方向。
- 项目人员通过平台上传人脸照片，平台将人员档案、人脸和门禁权限同步到设备。
- 设备接收人脸验证并产生通行事件，平台通过设备标识、人员编号和设备绑定的生效时间，将事件归属到具体项目和人员；晚到事件按发生时间归属原项目。
- 原始设备事件不合并、不修改；平台按“项目 + 人员 + 日期”汇总所有出入口的有效记录，生成考勤结果。

### 2.1.3考勤规则与异常处理

- 只要当天存在有效进门或出门记录，就算正常出勤；当天没有任何有效进出记录才算缺勤。
- 最早有效进门时间用于判断迟到，最晚有效出门时间用于判断早退。
- 进门和出门记录缺少一个方向时，仍算正常出勤，同时保留记录异常标识。
- 考勤管理作为 PC 端统一功能模块管理，支持按项目筛选、查询、补录、请假和导出；项目详情提供本项目考勤快捷入口。
- 考勤数据按项目归属，考勤计算主键为“项目 + 人员 + 日期”；项目负责人只能管理本项目，管理员可以跨项目管理。
- 支持项目级上下班时间、迟到宽限时间、早退宽限时间、工作日/休息日配置。
- 节假日和休息日生成“无需考勤”结果；非工作日有人进出时不统计考勤，只保留原始进出记录。
- 支持管理员登记请假。请假期间免除缺勤、迟到和早退判断。
- 请假只影响考勤，不影响门禁权限；请假与补录同时存在时，请假优先。
- 本期只提供补录，不提供直接修正；补录错误时允许作废补录记录，填写作废原因并重新计算平台考勤结果，设备原始事件不做修改。

### 2.1.4健康报告与年龄管理

- 健康报告不是必填项，仅作为人员资料和有效期信息展示；健康报告有效期按体检日期加一年计算，不参与门禁授权判断。
- 历史健康报告长期保存，支持上传图片，图片大小不超过 10M。
- 项目可设置年龄阈值，初始阈值为 60 岁，提前 30 天预警。
- 人员超过年龄阈值后次日默认禁止进入；确需继续进入时，由管理员或项目负责人直接登记特殊授权及有效期，平台不提供审批流程。

### 2.1.5工器具二维码管理

- 对现场手持工具、电焊机等工器具建立统一编码和二维码标识。
- 支持二维码生成、打印、扫码查看、工器具状态维护和定期检查。
- 默认每三个月检查一次，未按期检查时产生提醒。
- 不记录工器具借用流程，工器具转移项目后由新项目负责人负责后续检查。

### 2.1.6PC端和APP

- PC 端保留项目管理、施工队伍、专业、项目负责人、上下班时间等功能，取消二维码配置和地理围栏配置。
- PC 端增加人员人脸、健康报告、年龄限制、设备、同步状态、原始通行事件、考勤结果、人工补录、设备告警、操作日志和数据导出。
- APP 保留我的考勤、考勤概览、项目切换、个人信息和密码修改，取消扫码打卡和 APP 补录。

## **2.2项目主要岗位与分工**

- 管理员：负责平台整体管理，维护项目、人员、设备、权限、考勤和工器具信息，处理设备告警和人员补录。
- 项目负责人：负责本项目人员、人脸、设备、健康资料、考勤和工器具检查管理，查看本项目相关记录。
- 打卡人员：通过人脸设备完成现场进出，在 APP 查看本人考勤、个人信息和本人相关抓拍记录。
- 海康设备接入服务：负责设备登录、能力查询、人员人脸权限同步、实时事件接收和历史事件补传。

## **2.3解决方案整体架构**

本方案以“施工人员主数据—项目设备授权—设备通行事件—平台考勤计算”为主线，结合工器具二维码管理形成统一的项目现场管理平台。

### **2.3.1整体流程**

```text
项目管理
   ↓
项目绑定已登记海康设备并在绑定时配置出入口
   ↓
选择项目人员并上传人脸
   ↓
人员档案、人脸、门禁权限同步
   ↓
海康设备进行人脸验证和门禁通行
   ↓
实时事件接收 / 历史事件补传
   ↓
原始事件保存
   ↓
按项目、人员、日期生成考勤结果
   ↓
PC、APP查询和统计
```

### **2.3.2整体流程说明**

**总体架构**

- 平台以项目为业务管理单元，一个项目可以绑定多台设备，并在设备绑定关系中配置多个出入口。
- 项目设备关系由平台维护，设备事件到达后根据设备序列号或平台设备 ID 找到项目。
- 设备人员关系由 `employeeNo` 与平台人员 ID 建立映射，人脸编号与人员编号保持对应。
- 平台同时保存海康原始设备事件和平台计算后的考勤结果，两个层次的数据相互独立。

**与海康设备的集成**

- 设备登记后由接入服务登录海康设备，查询设备信息和门禁能力。
- 人员、人脸和门禁权限由平台发起同步。
- 实时通行通过海康门禁报警事件接收。
- 设备或平台恢复后，通过历史事件接口进行补传。
- 设备同步失败时记录失败原因和同步状态；平台要求撤销权限但设备同步失败时，设备保留原权限，并由平台记录同步异常。
- 平台所有告警统一通过站内信推送，不使用短信、邮件等其他方式。

# 三、详细方案

## 3.1项目与人员管理

### 3.1.1项目基本信息

**业务概况**

- 项目是人员、设备、考勤和工器具管理的基本业务单元。
- 现有系统项目管理功能继续保留，取消仅服务于二维码打卡的地理围栏和打卡范围配置。

**方案**

- 支持项目新增、编辑、查询和删除管理。
- 项目新增时维护项目名称、项目地址、项目负责人、上下班时间、迟到宽限时间、早退宽限时间、年龄阈值和年龄预警天数等基础信息。
- 项目编辑支持修改项目基本信息和考勤配置，不影响已有人员关系、设备关系和历史考勤记录。
- 项目查询支持按照项目名称、项目负责人、项目状态等条件查询，并查看项目人员、设备、考勤和工器具信息。
- 项目删除采用业务校验：没有人员、设备、考勤或工器具业务数据的项目可以删除；已经产生业务数据的项目不做物理删除，改为停用或归档，历史数据继续保留。
- 项目基本信息包括项目名称、项目地址、项目负责人、上下班时间、迟到宽限时间、早退宽限时间等。
- 项目设置年龄阈值和年龄预警天数，初始年龄阈值为 60 岁，预警时间为 30 天。
- 项目可以维护工作日、休息日和节假日规则。
- 项目可以维护项目人员、设备绑定关系和工器具；出入口名称和进出方向在绑定设备时配置。
- 项目停用或归档时，停用项目下全部设备并撤销相关人员的项目门禁权限；历史业务数据继续保留。
- 项目之间的数据相互隔离，管理员可以按照项目查询和导出数据。

### 3.1.2人员信息

**业务概况**

- 施工人员信息是人员授权、项目考勤、健康资料和年龄判断的基础。
- 现有系统人员信息需要扩展，形成统一人员资料库，减少同一人员重复录入和跨项目管理困难。

**方案**

- 人员信息包括姓名、身份证号、籍贯、民族、性别、出生日期、年龄、手机号、施工队伍、施工队伍负责人/老板组、专业/工种、是否工长、人员状态、人脸照片、健康报告和资质证书。
- 身份证号不允许重复，年龄根据身份证号自动计算，不允许手工修改。
- 资质证书非必填，录入后维护证书有效期和到期提醒。
- 支持人员增删改查和 Excel 批量导入。
- 人员主档案不因项目转移或人员离场删除。
- 身份证号、人脸、健康报告等字段的查看和导出受角色权限控制。
- 人员档案与平台登录账号分开管理，人员信息不放在用户、角色、权限模块中维护。
- 一个施工人员最多关联一个移动端账号；人员可以没有移动端账号，但不影响其项目人员关系和设备通行权限。
- 在人员详情中提供移动端账号开通、停用和重置入口；用户管理统一维护账号状态、角色和数据权限。
- 施工人员开通账号后分配“打卡人员”角色，只能登录 APP 查看本人信息、本人考勤、本人进出记录、本人相关抓拍和本人关联项目。

### 3.1.3项目人员关系

**业务概况**

- 一个施工人员可能先后或同时参与多个项目，人员主档案不能直接绑定单一项目。
- 项目人员关系还需要反映进场、离场和门禁授权状态。

**方案**

- 人员与项目采用独立关联关系，一个人员可以同时关联多个项目。
- 关系信息包括人员、项目、进场日期、离场日期、项目人员状态和项目门禁授权状态。
- 人员加入项目后，项目管理员可以为其上传人脸并启动设备同步。
- 人员离场后解除项目关系并撤销设备权限，但保留历史关系和历史考勤。
- 人员离开一个项目时，移除该项目 APP 数据查看范围和设备通行权限，但不影响其他项目的 APP 和设备权限。
- 人员离开全部项目时，可以停用移动端账号，但不删除人员档案和历史业务数据。
- 人员重新进入原项目时重新建立项目人员关系，并根据当前资格恢复设备授权。

### 3.1.4施工队伍和专业

**业务概况**

- 施工队伍和专业是人员分类、项目用工统计和考勤查询的重要基础资料。

**方案**

- 保留施工队伍管理和专业/工种管理。
- 人员关联项目时选择施工队伍、施工队伍负责人/老板组和专业/工种。
- 支持按照施工队伍、负责人、专业、项目和人员状态筛选人员。
- 支持将筛选结果导出为 Excel。

## 3.2海康设备与门禁管理

### 3.2.1设备信息

**业务概况**

- 海康设备是人员实际进出项目的执行终端，平台需要知道每台设备属于哪个项目、哪个出入口以及承担进门还是出门职责。

**方案**

- 设备信息包括平台设备 ID、海康设备序列号、设备名称、型号、固件版本、设备状态、最后连接时间和备注。
- 设备序列号是设备的稳定身份，不使用 IP 地址作为设备唯一标识。
- 设备登记与项目绑定分开管理。设备登记只建立全局物理设备档案，不直接归属项目，也不触发项目人员同步。
- 设备可以在项目门禁管理中绑定项目，并在绑定设置中选择出入口和方向。
- 一个项目可以绑定多台设备，一个出入口暂定配置一台进门设备和一台出门设备。
- 设备解除绑定或更换时，保留原设备历史事件和原项目归属。

设备登记流程为：

1. 系统管理员在“设备登记”页面登记海康设备，保存平台设备 ID、序列号、型号和连接信息；
2. 设备登记成功后进入“已登记、未绑定”状态；
3. 项目负责人在项目详情中发起设备绑定，并在绑定设置中选择出入口和方向；
4. 项目负责人从已登记且未绑定的设备中选择设备，保存项目绑定关系；
5. 绑定关系保存后，平台自动计算并同步当前项目人员、人脸和门禁权限。

项目负责人不能直接创建物理设备，只能在授权项目中选择已登记设备完成绑定。系统管理员可以登记设备、查看全量设备并处理设备停用、恢复和归档。

### 3.2.2项目与设备绑定

**业务概况**

- 项目与设备的关联决定设备打卡记录的项目归属。
- 同一项目可以有多个出入口，不同出入口的设备都参与本项目考勤统计。

**方案**

项目设备关系至少包括：

- 项目 ID；
- 平台设备 ID；
- 海康设备序列号；
- 出入口名称；
- 方向：进门/出门；
- 是否参与考勤；
- 绑定状态；
- 绑定生效时间和失效时间。

设备事件按照事件发生时间匹配设备项目绑定关系；设备更换项目时，原绑定关系结束，新绑定关系从新的生效时间开始，晚到事件仍按发生时间归属原项目，历史记录不重新归类。

项目门禁页面直接展示项目已绑定设备。绑定设备时选择已登记且当前未绑定其他项目的设备，同时填写或选择出入口名称和进出方向，不再单独维护项目出入口。出入口信息作为设备绑定关系的属性保存。同一物理设备同一时间只允许存在一个有效项目绑定关系，避免设备事件无法确定项目归属。

设备绑定完成后先进入“待同步/同步中”状态，人员、人脸和门禁权限全部同步成功后才显示为已生效。人员同步不在设备登记阶段执行，而是以项目绑定关系为范围，对项目下全部出入口设备进行全量或增量同步。

### 3.2.3人员、人脸和门禁权限

**业务概况**

- 设备只有同时具备人员档案、人脸资料和门禁权限，才能完成有效门禁授权。

**方案**

人员授权流程为：

1. 人员关联项目；
2. 项目管理员上传人脸照片；
3. 平台同步设备人员档案；
4. 平台同步设备人脸；
5. 平台同步门禁权限；
6. 平台展示每一步的同步状态。

人员、人脸和权限全部同步成功后，设备才允许人员通行。

健康报告不是授权条件。人员没有健康报告或健康报告已经过期时，仍然允许进入，平台只展示健康报告状态。

### 3.2.4设备同步状态

**业务概况**

- 人员同步失败、人脸同步失败或权限同步失败，都会影响人员是否能够正常通行，平台需要将三类状态分别展示。

**方案**

- 人员档案同步状态：未同步、同步中、成功、失败；
- 人脸同步状态：未同步、同步中、成功、失败；
- 门禁权限同步状态：未同步、同步中、成功、失败；
- 设备授权状态：允许进入、禁止进入、已撤销、同步异常；
- 保存最后同步时间、失败原因和重试次数。

首次授权失败时，设备侧没有有效权限，人员不允许进入。平台要求撤销权限但设备同步失败时，保留设备侧原权限，并在平台产生同步异常记录。

## 3.3人脸考勤管理

### 3.3.1人脸录入

**业务概况**

- 平台完成人员人脸录入，设备负责后续识别。本期不支持通过海康设备现场采集人脸。

**方案**

- 每个人员暂保存一张人脸照片。
- 人脸照片支持图片格式，单张图片不超过 10M。
- 项目管理员或其他有权限人员可以上传、替换和删除人脸照片。
- 不需要公司管理员审核，不单独设置人脸审核状态。
- 人员本人可以查看本人照片，但不能自行修改。
- 人脸照片更新后自动同步所有关联项目设备。

### 3.3.2实时打卡记录

**业务概况**

- 设备将人脸识别结果和门禁事件回传平台，平台将每条设备事件保存为原始记录。

**方案**

- 人脸识别成功即计入有效打卡。
- 人脸识别成功但没有门禁开门反馈时，仍按有效打卡处理，同时保留设备异常信息。
- 人脸识别失败作为安全日志。
- 权限过期人员尝试进入产生告警；未登记人员不产生独立告警，只保留刷脸记录。
- 保存成功通行、识别失败和权限过期人员的抓拍照片，不保存未登记人员抓拍照片。

### 3.3.3历史事件补传

**业务概况**

- 实时事件可能因设备或平台暂时不可用而延迟到达，需要通过设备历史事件补传保证记录完整。

**方案**

- 接入服务按设备时间、事件流水号或最后处理位置查询历史事件。
- 历史事件与实时事件采用同一套保存和计算逻辑。
- 通过设备 ID、事件流水号、事件时间和人员进行去重；同一设备重复推送同一事件时只保留一条，实时事件和历史补传事件采用同一套去重规则，并保留事件来源标识。

### 3.3.4考勤计算

**业务概况**

- 考勤统计不按单台设备分别计算，而是按项目汇总同一人员在所有出入口的有效记录。

**方案**

- 考勤统计主键维度为项目、人员和日期。
- 原始设备事件不合并、不修改；考勤计算时统一汇总。
- 考勤日期以设备事件时间为准；设备时间应通过设备自身时间同步能力保持准确。
- 当天存在任意有效进门或出门记录，计为正常出勤。
- 当天没有任何有效进出记录，计为缺勤。
- 最早有效进门时间判断迟到。
- 最晚有效出门时间判断早退。
- 进门、出门任一方向缺失时仍算正常出勤，保留异常标识。
- 一个人一天多次进出，出勤人数只统计一次。
- 不计算停留时长、加班和夜班跨日考勤。

考勤判断公式：

```text
最早进门 > 上班时间 + 迟到宽限时间 → 迟到
最晚出门 < 下班时间 - 早退宽限时间 → 早退
无任何有效进出记录 → 缺勤
```

### 3.3.5节假日、休息日和请假

**业务概况**

- 如果项目处于休息日、节假日或人员已经请假，系统不应直接按照普通工作日判断缺勤。

**方案**

- 支持项目配置工作日、休息日和节假日。
- 节假日和休息日生成“无需考勤”结果，非工作日有人进出时不统计考勤，只保留原始进出记录。
- 管理员按人员、项目和日期登记请假。
- 请假期间免除缺勤、迟到和早退判断。
- 请假只影响考勤，不影响门禁权限；请假与补录同时存在时，请假优先。
- 不对接外部请假系统。

### 3.3.6人工补录

**业务概况**

- 设备异常、人员漏打或其他特殊情况可能导致当天缺少进门/出门记录，需要管理员补充考勤依据。

**方案**

- 本期只提供补录，不提供直接修正平台考勤结果；错误补录允许作废，作废必须填写原因并保留操作日志。
- 管理员可以补录进门记录，也可以补录出门记录。
- 补录必须填写原因，不需要审批。
- 同一天允许多次补录同一方向记录，补录记录不做去重。
- 补录记录单独保存，并记录操作人、时间、补录方向和补录原因。
- 补录或作废后系统重新计算当天迟到、早退、缺勤和无需考勤结果。
- 海康原始事件始终保持不可修改。

## 3.4健康报告与年龄限制管理

### 3.4.1健康报告

**业务概况**

- 健康报告是人员资料和有效期展示信息，不作为本期门禁授权条件。

**方案**

- 健康报告非必填。
- 支持上传图片，图片大小不超过 10M。
- 不需要人工审核。
- 有效期按照体检日期加一年计算。
- 页面展示有效、即将到期或已过期状态。
- 不设置健康报告到期提醒，不向角色发送通知。
- 没有健康报告或健康报告过期不影响人员进入。
- 历史健康报告长期保存。

### 3.4.2年龄限制

**业务概况**

- 年龄限制是项目人员门禁授权的重要业务规则，用于控制超过项目年龄要求的人员进入项目。

**方案**

- 项目设置年龄阈值，初始阈值为 60 岁。
- 年龄根据身份证号自动计算。
- 提前 30 天产生年龄预警。
- 年龄预警通过站内消息通知管理员和项目负责人，并在页面展示，不生成独立告警记录。
- 人员超过阈值后次日默认禁止进入。
- 确需继续进入时，由管理员或项目负责人直接登记特殊授权，平台不提供审批流程。
- 特殊授权记录授权人、授权依据、生效时间和失效时间。
- 在特殊授权范围和有效期内恢复设备权限。
- 特殊授权有效期结束后恢复禁止状态。

## 3.5设备告警和抓拍管理

### 3.5.1设备告警

**业务概况**

- 设备离线、权限过期或同步失败都会影响现场管理，需要让管理员和项目负责人及时了解异常；未登记人员只保留刷脸记录，不单独产生告警。

**方案**

- 告警类型包括权限过期人员、设备故障、设备离线、人员同步失败、人脸同步失败和权限同步失败。
- 告警通知管理员和项目负责人。
- 所有告警统一通过站内信推送。
- 不设置告警等级，不需要人工确认关闭。
- 设备恢复在线后自动关闭离线告警。
- 支持告警记录查询。

### 3.5.2抓拍照片

**业务概况**

- 抓拍照片用于核验人员通行和处理异常记录，需要与原始事件和考勤记录关联。

**方案**

- 保存所有成功通行抓拍。
- 保存人脸识别失败抓拍。
- 保存权限过期人员抓拍。
- 不保存未登记人员抓拍。
- 考勤记录中直接查看关联抓拍。
- 管理员和项目负责人可以查看。
- 打卡人员本人可以查看本人相关抓拍。
- 抓拍照片永久保存。

## 3.6工器具二维码管理

### 3.6.1工器具信息

**业务概况**

- 工器具管理的目标不是完整的借用和财务资产管理，而是对现场工具进行统一编码、状态管理和定期安全检查。

**方案**

- 工器具信息包括工器具编号、名称、型号、所属项目、使用状态、二维码、检查周期和最近检查记录。
- 平台自动生成唯一编码并生成二维码。
- 二维码可打印为标签，扫码查看工器具最新状态。
- 支持按照设备编号、型号、项目和状态搜索。
- 支持跨项目查询可用工器具。
- 不强制记录借用流程。

### 3.6.2工器具检查

**业务概况**

- 项目管理人员需要定期检查现场工器具，避免设备长期未检验仍处于使用状态。

**方案**

- 检查周期默认三个月。
- 检查记录包括检查时间、检查人、检查结果、问题描述和备注。
- 到期未检查时产生提醒。
- 工器具转移项目后，由新项目负责人承担后续检查责任。
- 支持查看工器具检查历史。

## 3.7PC端和APP功能

### 3.7.1PC端功能

**业务概况**

- PC 端是管理员和项目负责人维护人员、设备、考勤和工器具的主要工作台。

**方案**

PC 端保留：

- 施工队伍管理；

- 项目负责人及考勤规则配置；
- 上下班时间配置；
- 项目人员管理。

PC 端取消：

- 二维码打卡；
- 二维码配置；
- 地理围栏和打卡范围配置。

PC 端新增：

- 人员人脸信息；
- 健康报告；
- 年龄限制和特殊授权记录；
- 海康设备管理；
- 人员、人脸和权限同步状态；
- 原始通行事件；
- 平台考勤结果；
- 人工补录；
- 请假登记；
- 设备告警；
- 抓拍照片；
- 操作日志；
- 工器具二维码和检查管理。

### 3.7.2APP功能

**业务概况**

- APP 继续服务于施工人员的个人信息和考勤查询，不再承担扫码打卡和人工补录。

**方案**

- 保留我的考勤；
- 保留考勤概览；
- 保留项目切换；
- 展示进门、出门、迟到、早退和缺勤；
- 展示本人相关人脸同步状态；
- 保留个人信息和密码修改；
- 施工人员通过移动端账号登录，账号状态和可查看项目范围由平台用户权限控制；
- 人员关联多个项目时支持项目切换，只展示当前账号有权查看的项目数据；
- 取消扫码打卡入口；
- 不允许 APP 进行补录或考勤修正。

## 3.8权限管理

**业务概况**

- 系统中包含身份证号、人脸照片、健康报告、抓拍照片和考勤记录，需要按照管理职责控制查看和操作范围。

**方案**

- 管理员和项目负责人可以查看和维护人员信息、人脸照片、健康报告、原始设备事件、考勤结果和工器具记录。
- 管理员和项目负责人可以执行人员补录、设备管理、人员同步和告警查询。
- 管理员和项目负责人可以导出人员和考勤数据。
- 管理员、项目负责人和打卡人员本人可以按权限查看相关抓拍照片。
- 打卡人员只能查看本人考勤、个人信息和本人相关记录。
- 人员档案、移动端账号、角色权限和设备门禁权限分别管理，通过人员 ID 和账号关联关系建立映射。
- 移动端账号停用不等同于设备权限撤销，账号登录权限和门禁通行权限分别控制。
- 平台不提供审批流程；年龄超限继续进入时，仅维护已确认的特殊授权记录，不在平台内发起审批流转。
- 本期不提供远程开门。

# 五、与相关系统的集成

## 5.1与海康设备 SDK 的集成

- 通过海康设备网络 SDK 完成设备初始化、设备登录和设备能力查询。
- 通过人员管理接口完成设备人员档案新增、修改和删除。
- 通过人脸库接口完成人员人脸照片上传、更新和删除。
- 通过门禁权限接口完成项目人员的通行权限配置。
- 通过门禁报警回调接收实时通行事件。
- 通过历史事件接口补传设备未及时上传的历史通行记录。
- SDK、设备登录凭据和设备接入逻辑由后端设备接入服务或现场网关负责，浏览器前端不直接加载 SDK，不保存明文设备密码。

接入服务需要保存以下映射关系：

```text
平台 project_id ↔ 平台 device_id ↔ 海康设备序列号
平台 person_id  ↔ 海康 employeeNo ↔ 海康人脸 FPID
设备绑定方向     ↔ 进门 / 出门
```

## 5.2与现有平台的集成

- 保留现有项目、人员、施工队伍、专业和基础信息管理能力。

- 原有二维码打卡数据作为历史数据保留，不再产生新的二维码打卡记录。
- 现有 APP 保留查询类功能，取消二维码打卡和 APP 补录。
- 具体 API、数据库和源代码改造方式在后续技术设计阶段确定。

## 5.3与住建委平台的集成

- 本版暂不建设住建委数据对接。
- 后续根据住建委接口要求，另行确定设备直传或平台转发方案。

## 5.4网络和网关方案

- 本版不确定中心直连、现场网关或其他接入方式。

## 5.5海康门禁 SDK 对接的最小落地项目

### 5.5.1落地目标和验收基线

本节用于定义第一阶段可实施、可验证的最小闭环，不替代后续完整实施方案。建议以“单一已确认设备型号、单个试点项目、一个出入口”为首轮验收基线；实际设备型号、设备数量和现场网络确认后，再扩展多型号、多项目和多出入口能力。

最小闭环为：

```text
设备连接与登录
    ↓
设备身份和门禁能力查询
    ↓
项目、出入口和门编号绑定
    ↓
人员、人脸和门禁权限同步
    ↓
实时通行事件接收
    ↓
历史事件补传、去重和原始事件保存
    ↓
平台考勤结果生成
```

### 5.5.2最小配置参数

| 配置分类 | 最小参数 | 说明 |
|-|-|-|
| 平台设备档案 | 平台设备 ID、设备名称、海康序列号、设备型号、固件版本 | 平台设备 ID 为平台主键，海康序列号为设备稳定身份 |
| 设备登录 | 设备 IP/域名、通信协议、SDK 服务端口、HTTP/HTTPS 端口、用户名、密码 | 海康私有 SDK 端口通常为 8000，ISAPI 端口通常为 HTTP 80 或 HTTPS 443，最终以设备配置为准 |
| 安全连接 | 是否启用 TLS、证书/认证方式、代理或 EHome 参数 | 仅在现场采用 HTTPS、TLS、代理或 EHome 时启用 |
| 门禁拓扑 | 门编号、控制器编号、控制器门编号、读卡器编号 | 用于将 SDK 事件映射到具体出入口；门编号从 1 开始，具体能力以设备查询结果为准 |
| 项目绑定 | 项目 ID、出入口 ID、进出方向、绑定生效时间、是否参与考勤 | 平台业务配置，不能由设备序列号单独推断 |
| 人员映射 | 平台人员 ID、海康 employeeNo、人脸 FPID、人脸库 ID | 建议采用“以人为中心”的人员管理方式，保持 employeeNo 与 FPID 一致 |
| 门禁授权 | 授权门、权限生效时间、权限失效时间、验证方式、撤销状态 | 人脸和门禁权限分别记录同步状态 |
| 事件接收 | 报警回调、实时布防、断网补传、抓拍图片上传方式 | 实时和历史事件使用统一入库和去重规则 |

设备密码必须加密保存，只允许后端设备接入服务使用；前端只展示连接状态、最后连接时间和脱敏后的设备信息。

### 5.5.3最小实施顺序

1. **准备设备参数**：确认设备型号、固件版本、设备 IP/域名、登录账号、通信端口、门数量和现场网络可达性。
2. **实现设备连接**：初始化 SDK，调用设备登录接口，读取设备序列号、型号、固件版本和门禁能力；连接失败时保存 SDK 错误码和失败原因。
3. **实现设备绑定**：配置项目、出入口、进出方向、门编号及绑定生效时间，建立平台设备 ID、设备序列号和项目的映射关系。
4. **实现人员同步**：下发项目人员档案、人脸图片和门禁权限，分别记录人员、人脸、权限三类同步状态。
5. **实现事件闭环**：建立门禁事件接收通道，保存实时事件；设备重连后补传历史事件，首阶段暂按设备、事件流水号、事件时间和人员进行去重，上线前根据实机事件字段确认最终唯一键。
6. **接入平台考勤**：按照现有“项目 + 人员 + 日期”规则生成考勤结果，并展示设备状态、同步失败原因、权限差异和事件来源。

### 5.5.4第一阶段包含和不包含的内容

第一阶段必须包含：

- 设备登记、连接测试、登录状态和设备能力查询；
- 一个试点项目的设备、出入口和门编号绑定；
- 项目人员、人脸和门禁权限的新增、更新、撤销和失败重试；
- 实时门禁事件接收、历史事件补传、去重和原始事件留存；
- 设备离线、同步失败和平台权限与设备权限不一致的状态展示；
- 设备原始事件到项目、人员和进出方向的映射；
- 基于有效事件生成平台考勤结果。

第一阶段暂不包含：

- 多品牌或多型号的兼容性适配；
- 远程开门、远程人脸采集和移动端补录；
- 住建委平台数据对接；
- 完整的公网穿透、集群、高可用和跨地域网关方案；
- 现场安装施工、设备采购和最终网络施工方案。

### 5.5.5最小落地完成判定

满足以下条件，视为海康门禁 SDK 最小落地闭环完成：

- 使用平台配置的地址、端口和账号可以成功登录试点设备；
- 平台能读取并保存设备序列号、型号、固件版本、门数量和设备能力；
- 一个项目的一个出入口可以正确绑定到指定设备和门编号；
- 一名测试人员可以完成档案、人脸和门禁权限同步，并能验证权限撤销；
- 测试人员刷脸通行后，平台能收到实时事件并正确归属项目、人员和方向；
- 断开设备或接入服务后恢复连接，历史事件可以补传且不产生重复记录；
- 原始设备事件保持只读，平台可以生成对应的日考勤结果；
- 登录失败、同步失败、设备离线和权限差异均能显示原因和时间；
- 设备密码不出现在前端、浏览器日志或普通业务接口响应中。
