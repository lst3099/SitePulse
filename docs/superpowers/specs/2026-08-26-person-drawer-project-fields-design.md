# 人员档案新增/编辑移除项目关系字段设计

## 背景

人员档案抽屉当前在“项目关系”区块中展示并提交“所属项目”“关系类型”“人员状态”。本次调整仅针对新增和编辑人员档案的表单，避免在人员基础资料维护中直接维护项目关系字段。

## 目标与范围

- 新增、编辑模式不展示“项目关系”区块及其三个字段：所属项目、关系类型、人员状态。
- 查看模式继续展示项目关系只读信息，保留现有的项目关系可见性与权限判断。
- 已有人员的项目关系数据不因编辑基础资料而被清空、替换或新增。
- 新增人员默认不绑定项目，沿用当前未绑定人员的保存规则。
- 不修改列表筛选、账号绑定、门禁权限和项目关系数据结构。

## 设计

### 表单展示

`PersonDrawerContent` 根据 `mode` 条件渲染项目关系区块：

- `mode="view"`：保留现有项目关系展示，用于查看所属项目、关系类型和人员状态。
- `mode="edit"`：不渲染该区块，也不将三个字段注册为表单字段。

编辑模式的表单初始值同时剔除项目关系派生字段，避免未展示字段因初始值被带入提交结果。

### 保存与权限

- 编辑时保存基础资料仍调用现有 `buildPersonRecord`，项目关系输入保持为空，关系列表从现有 `projectPeople` 数据重建并原样保留。
- 新增时不产生项目关系；系统管理员可创建未绑定人员，其他角色继续遵循现有项目作用域规则。
- `submitPersonEdit` 使用当前人员已有项目或当前可编辑项目作为权限校验范围，不依赖已移除的 `projectId` 表单字段。

## 测试策略

在现有 `src/components/AppShell.test.jsx` 中增加回归覆盖：

- 编辑模式不包含项目关系标题和三个字段标签。
- 新增模式不包含项目关系标题和三个字段标签。
- 查看模式仍包含项目关系标题。
- 现有保存相关权限与基础字段校验保持通过。

## 验收标准

1. 打开“新增人员”或“编辑人员”抽屉时，页面不出现“项目关系”“所属项目”“关系类型”“人员状态”。
2. 打开“查看”抽屉时，项目关系只读信息仍可见。
3. 编辑已有人员并保存后，其原有项目绑定关系、列表项目数量和账号绑定上下文不变。
4. 新增人员保存后没有项目绑定。
5. 相关测试与生产构建均通过。
