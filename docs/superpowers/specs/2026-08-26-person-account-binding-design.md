# 人员—系统账号绑定设计

## 背景

人员管理页当前能看到人员档案、项目关系、门禁与人脸状态，但没有清楚体现施工人员和当前系统账号之间的关联。方案文档已明确：人员档案与平台登录账号分开管理，一个施工人员最多关联一个移动端账号；账号状态、项目数据权限和设备门禁权限分别控制。

本次原型补齐人员管理页的账号关系展示和操作，面向系统管理员的对外演示路径优先，同时保持现有用户权限页的账号生命周期职责。

## 目标与非目标

### 目标

- 在人员表格中直接显示当前账号绑定状态。
- 对已绑定、未绑定、账号停用三种状态提供明确的视觉反馈。
- 在人员管理页提供绑定、解绑和查看账号详情入口。
- 让演示者能明确理解：账号关系与设备门禁权限独立管理。
- 绑定或解绑后，表格状态和详情抽屉立即更新，并写入本地演示操作日志。

### 非目标

- 不在人员管理页重建账号角色、项目权限或登录凭据管理。
- 不删除账号；解绑仅解除人员—账号关系，账号本身保留在用户权限页。
- 不因账号未绑定或账号停用而自动撤销设备门禁权限。
- 不改变人员档案、项目人员关系、人脸登记和门禁同步的既有业务规则。

## 页面结构

采用 A「表格直出」方案，最终网页按纵向页面展示，不保留方案评审用的并排卡片、推荐标签或适合/优势说明。

### 筛选区

现有姓名和项目筛选保留，并新增账号绑定状态筛选：全部、已绑定、未绑定、账号已停用。四个选项互斥：

- 已绑定：存在关联账号且账号状态为启用；
- 未绑定：不存在关联账号；
- 账号已停用：存在关联账号且账号状态为停用；
- 全部：包含以上三类。

查询仍为本地演示筛选，不引入后端请求。

### 人员表格

在现有人员信息基础上增加/调整以下关系信息：

- 账号绑定：状态标签“已绑定 / 未绑定”。
- 账号名称：已绑定时显示账号名称，未绑定时显示“未关联系统账号”。
- 账号状态：已绑定且账号停用时显示“账号已停用”；未绑定不显示虚构的账号状态。
- 独立权限提示：在账号关系摘要中显示“门禁权限独立管理”，避免把账号状态理解为门禁状态。

操作列按当前状态显示：

- 已绑定：查看账号、解绑。
- 未绑定：绑定账号。
- 已绑定但账号停用：查看账号、解绑；账号启停仍由用户权限页负责。

### 关系抽屉

绑定、解绑、查看详情统一使用右侧抽屉，字段按纵向顺序展示：

1. 人员身份：姓名、人员编号、项目摘要。
2. 登录账号：账号名称/账号 ID；未绑定时显示空状态。
3. 账号角色：绑定施工人员账号后默认使用“打卡人员”角色。
4. 账号状态：启用、停用，或未绑定。
5. 门禁权限：当前门禁状态，并标注“与登录账号独立管理”。
6. 可见范围：绑定后可查看本人信息、本人考勤、本人进出记录、本人抓拍及关联项目。
7. 操作区：绑定已有账号、解绑或查看用户权限；不提供删除账号入口。

绑定账号时，只能从以下条件都满足的已有账号中选择：账号角色为“打卡人员/施工人员”、账号状态为启用、尚未关联其他施工人员。一个施工人员只能绑定一个账号，一个账号不能同时绑定多个施工人员。绑定只建立人员与账号的唯一关联，不自动修改账号的 `projectIds`；候选账号必须已经覆盖该人员至少一个当前有效项目。当前有效项目以现有 `scopedProjects` 结果中项目状态为 `active` 的项目为准。账号可见范围沿用绑定前已有的 `projectIds`，绑定操作不新增或扩大项目数据权限，项目数据权限仍由用户权限页单独维护。对于本地演示，选择账号后立即更新状态并提示成功。

解绑时使用二次确认，确认文案说明：解绑不会删除账号、人员档案、历史考勤或门禁权限。解绑成功后回到未绑定状态。

## 数据模型与状态

沿用现有 `people` 与 `accounts` mock 数据，通过 `personId` 建立唯一关系。账号关系的唯一状态源提升到 `App.jsx` 的 `accounts` 状态，并同时传给人员管理页和用户权限页；两页通过 `onAccountsChange` 更新同一份数组，不各自维护独立副本：

- 人员记录：`personId` / `id`。
- 账号记录：`accountId`、`name`、`personId`、`role`、`status`、`projectIds`；账号名称直接使用现有 `accounts` mock 数据的 `name` 字段。
- 绑定关系：由账号记录的 `personId` 反向计算，不在人员档案中维护第二份账号主数据。

演示数据增加一个未关联、启用、施工人员角色的可绑定账号，用于演示李娜的绑定流程。

状态计算：

| 人员与账号关系 | 表格显示 | 可用操作 |
| --- | --- | --- |
| 无关联账号 | 未绑定 / 未关联系统账号 | 绑定账号 |
| 关联且账号启用 | 已绑定 / 账号名称 | 查看账号、解绑 |
| 关联且账号停用 | 已绑定 / 账号已停用 | 查看账号、解绑 |

账号状态与门禁权限不得互相推导。门禁信息继续由人员、项目关系和设备授权数据计算。

## 操作日志

绑定和解绑复用现有 `onOperationLog` / `appendOperationLog` 链路，写入操作日志页面可见的最小字段：

- `projectId`：人员当前主项目；
- `operatorId`：当前操作账号；
- `operation`：`accountBind` 或 `accountUnbind`；
- `module`：`people`；
- `targetId`：人员 ID；
- `accountId`：被绑定/解绑的账号 ID；
- `occurredAt`：演示日期时间；
- `reason`：绑定账号或解除人员账号关联。

日志只读，不在本次人员页增加日志展示区。

## 权限边界

- 系统管理员：可查看全部人员关系，并执行绑定、解绑和详情查看。
- 项目负责人：按授权项目查看关系；本期不执行账号绑定/解绑，账号操作仍由系统管理员完成，不扩大为跨项目账号管理。
- 施工人员：不进入 PC 人员管理页，继续只使用移动端本人范围。

敏感字段遵循既有脱敏规则；账号详情不新增身份证明的明文展示。

## 验收标准

- 人员表格默认能看出每一行是否绑定系统账号。
- 过滤“未绑定”后只显示未关联账号的人员。
- 对张伟可演示“已绑定、查看账号、解绑”。
- 对李娜可演示“未绑定、绑定已有账号”，绑定后显示账号名称和启用状态。
- 解绑后人员仍在表格中，人员档案、项目关系、历史考勤和门禁状态不变。
- 账号停用时，人员页显示账号已停用，但不自动改变门禁状态。
- 不会创建第二个同一施工人员账号，也不会把同一账号绑定给多个施工人员。
- 绑定和解绑都会显示本地演示成功提示并写入操作日志。
- 页面桌面端为纵向真实页面布局，表格可读，不出现大面积并排评审信息或竖排字段。
- 现有测试、构建和页面路由不受影响。
